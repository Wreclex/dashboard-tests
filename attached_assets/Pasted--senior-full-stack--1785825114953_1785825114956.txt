# ЦЕЛЬ ЗАПРОСА
Создать полностью рабочий веб-дашборд на Replit, который автоматически собирает данные из личного кабинета системы «Мои Звонки» (https://ukmain.moizvonki.ru/dashboard/) и отображает три ключевые метрики:
1. «Трафик» — суммарное время совершённых звонков
2. «Кол-во звонков» — количество попыток дозвона
3. «Плотность работы» — количество звонков, делённое на длительность смены (по умолчанию 9.5 часов)

- Необходима автоматизация: дашборд должен сам получать данные без ручных действий (или с минимальными ручными действиями).
- Среда разработки и хостинга: Replit.
- Пользователь — менеджер по продажам, не профессиональный разработчик, поэтому код должен быть максимально простым, надёжным и с понятными инструкциями по настройке.

# ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ И АРХИТЕКТУРА

## Сбор данных (основной путь — автоматизация)
Реализуй ОДИН из подходов, выбрав наиболее надёжный для Replit:

### Вариант A (предпочтительный): Парсинг внутренних HTTP-запросов ЛК
- Пользователь один раз заходит в ЛК «Мои Звонки» через браузер, открывает DevTools → Network, нажимает кнопку «Сформировать» и копирует:
  - URL внутреннего запроса, который возвращает данные отчёта
  - Заголовки запроса (Headers), особенно Cookie и/или Authorization
  - Тело ответа (JSON или HTML), чтобы понимать структуру данных
- Напиши скрипт на Python (requests), который воспроизводит этот запрос, используя данные из переменных окружения Replit (Secrets):
  - [MOIZVONKI_COOKIES] — строка cookies из личного кабинета
  - [MOIZVONKI_REPORT_URL] — URL внутреннего запроса для получения данных
  - [MOIZVONKI_HEADERS] — опционально, дополнительные заголовки, если нужны
- Скрипт должен обрабатывать ответ и извлекать: суммарное время звонков, количество попыток дозвона.
- Если структура ответа неизвестна, сделай гибкий парсер с отладочным выводом сырых данных.

### Вариант B (запасной): Browser automation через Playwright
- Если внутренние запросы не удаётся воспроизвести (защита от ботов, динамический рендеринг, JS-генерация данных), используй Playwright для:
  - Автоматического логина в ЛК (логин/пароль из переменных окружения [MOIZVONKI_LOGIN] и [MOIZVONKI_PASSWORD])
  - Перехода на https://ukmain.moizvonki.ru/dashboard/
  - Нажатия кнопки «Сформировать»
  - Ожидания загрузки данных
  - Скачивания CSV или парсинга DOM
- Учти, что в Replit нужно установить зависимости: `playwright install chromium --with-deps`
- Используй headless-режим и таймауты.

### Вариант C (fallback): Ручная загрузка CSV
- Если автоматизация не работает, дашборд должен позволять загрузить CSV-файл вручную через форму на странице.
- Парсер CSV должен извлекать те же метрики: суммарное время, количество звонков.
- Сделай парсер гибким: пользователь сможет указать, какие колонки соответствуют времени и количеству звонков, или парсер должен автоматически искать колонки по ключевым словам («время», «длительность», «звонки», «попытки»).

## Хранение данных
- Используй SQLite или JSON-файл для хранения истории метрик по дням.
- Каждая запись: дата, трафик (в секундах или минутах), кол-во звонков, плотность.
- История нужна для графика динамики по дням.

## Бэкенд (Python + Flask)
- Эндпоинты:
  - GET / — главная страница дашборда
  - GET /api/metrics — текущие метрики в JSON
  - POST /api/refresh — принудительное обновление данных (запуск сбора)
  - POST /api/upload-csv — загрузка CSV (fallback)
  - GET /api/history — история метрик для графика
  - POST /api/settings — сохранение длительности смены и интервала обновления
- Веб-сервер должен слушать 0.0.0.0 и порт 5000 (или 8080), чтобы Replit корректно пробросил ссылку.
